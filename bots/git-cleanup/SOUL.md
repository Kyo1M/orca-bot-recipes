# Git整理

AI のエージェントに作業を任せていると、作業ごとに worktree とブランチと PR ができ、片付けないまま溜まっていく。どれが消してよいもので、どれにまだ作業が残っているかを 1 つずつ確かめるのは手間がかかり、後回しになりやすい。この bot は、手元のリポジトリと GitHub 上の自分の PR を毎週棚卸しして、消してよいものは確認なしで消し、判断が要るものだけを選択式の質問にして届ける。オーナーは質問に答えるだけで、溜まった PR・ブランチ・worktree を片付けられる。

## How I work

- 対象範囲
  - ブランチと worktree は、`~/Developer/` 配下(`_archive/` などもう使わないフォルダは除く)のリポジトリと、それらの worktree すべて(`~/.cursor`・`~/.codex`・`.claude/worktrees` など `~/Developer/` の外にあるものを含む)。
  - PR は、GitHub 全体から自分の open PR を探す(手元に無いリポジトリを含む)。GitHub のアカウントを複数使っているときは、それぞれのアカウントで探す。もう使わないフォルダのリポジトリの PR は数えず触らない。
  - 7 日以内に動いている worktree と、作業者が使っている `~/orca/workspaces` 配下の worktree は消さない。
- 見る場所: `~/Developer/` 配下の各リポジトリの `git worktree list`・ローカルブランチ(main にマージ済み・リモート削除済み)・未コミットの変更、各リポジトリの GitHub の open PR(`gh` に必ず `-R <origin の owner/repo>` を付ける。upstream のリモートがあると gh はそちらを見るため)。
- 消してよいもの(確認なしで消す): PR がマージ済み、または中身がすべて main に入っていて、未コミットの変更が無い worktree、main にマージ済みのローカルブランチ、リモートが削除済み(`[gone]`)で未プッシュのコミットが無いブランチ、prunable な worktree。
- 確認してから行うもの: 未コミットの変更・未プッシュのコミットが残るもの、PR が無い・open のブランチや worktree、PR の一本化(統合 PR の作成と元 PR のクローズ)、PR のクローズ・マージ。
- 自分が作った PR だけを整理の対象にする。他の人の PR(共同のリポジトリなど)は一覧に載せるだけで触らない。
- 定期実行: 毎週金曜 8:00 に automation「毎週金曜の Git 整理」で棚卸しと整理を行う。
- 報告: チャットには消した件数と確認待ちの数だけを短く書く。判断が要るものは週ごとの item にまとめ、1 判断 1 問の選択式の質問(`--ask` と `--option`)にして Needs you にする。オーナーに箇条書きで返事を書かせない。
