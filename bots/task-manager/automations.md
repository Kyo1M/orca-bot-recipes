# タスク管理の定期実行

4 種類の定期実行を組み合わせる。どれも台帳と `priorities.md` は読むだけで、台帳の書き換えはオーナーの返事を受けてからチャットで行う。

| 定期実行 | いつ | 何をする | 結果の出し先 |
|---|---|---|---|
| 毎朝のタスク確認 | 月〜土 9:00 | 今日から 7 日の段取りと状態の更新案 | 新しいチャットで実行し、結果を Home チャットへ。更新案は item で聞く |
| 日曜のタスク週次整理 | 日曜 9:00 | 来週の段取りと、この 1 週間の状態の更新案 | 新しいチャットで実行し、結果を Home チャットへ |
| Home チャットのリセット | 日曜 8:50 | 週次整理を新しい Home チャットで受け取るため、Home チャットを始め直す | 何も出さない(失敗したときだけ 1 行) |
| ずらせない予定のリマインド | 予定の前日 18:00 など | 予定までに仕上げるものと、関係するタスクの状態 | 新しいチャットで実行し、結果を Home チャットへ |

- 時刻はホストの時刻で動く。別のタイムゾーンで動かしたいときは `--timezone` を付ける。
- Mac がスリープしていて時刻を過ぎたときに後から 1 回だけ動かすには、`--missed-run-grace-minutes`(例 720)を付ける。
- プロンプトの `<your-hub-repo>` はハブのリポジトリの名前に置き換える。bot の定期実行は bot のフォルダで動くので、`report-policy.md`・`fixed-events.md` はフォルダの名前を書かずに読める。

## 作り方

bot のチャットで「次のプロンプトで、毎朝 9:00(月〜土)の定期実行を作って」と頼むと、bot が作る。自分で作るときは、下のプロンプトを置き換えてからファイル(例 `morning.txt`)に保存し、次のコマンドを使う。

```sh
orca automations create --bot "タスク管理" --name "毎朝のタスク確認" \
  --trigger "0 9 * * 1-6" --runs-in new --results-to chat \
  --missed-run-grace-minutes 720 \
  --prompt "$(cat morning.txt)"
```

## 毎朝のタスク確認

- いつ: `0 9 * * 1-6`(月〜土 9:00)

```text
毎朝のタスク確認。これからやるタスクを取り組みごとに見渡し、今日の段取りを決める。

ハブのリポジトリ(~/Developer/<your-hub-repo>)の task-ledger skill(.agents/skills/task-ledger/SKILL.md)の「1. 一覧」の手順 1-1〜1-2 で、projects.yaml の全プロジェクトの台帳と priorities.md を読み、自分の担当のタスクを集める(read: origin/main のプロジェクトは fetch してから origin/main を読む)。読むだけで、台帳・priorities.md・どのリポジトリのファイルも書き換えない。コミットもしない。

出し方は この bot のフォルダの report-policy.md(タスク整理の方針)に従う。必ず最初に読む。方針と下の指示が食い違うときは方針を優先する。
- プロジェクトごと(projects.yaml の順)に見出しを分け、その中を方針のテーマで分ける。
- 方針のテーマに当たらないタスクは「未分類」にまとめ、最後に振り分けを聞く 1 行を添える。
- タスクは方針のとおり、プロジェクトごとに 1 つの表で出す。タスクは要点が分かる長さに縮めてよい。共同担当は「(共同: <自分以外の担当>)」を添える。
- SKIP・fetch の失敗があれば冒頭に書く。
- 日本語で、前置きなしに結果だけを書く。

この回で書くもの:
- 冒頭の 1 行: 今日の日付と「今日 n件・7日以内 n件・進行中 n件」。
- 「ずらせない予定」: この bot のフォルダの fixed-events.md を読み、今日から 7 日以内の予定を、日時・予定・仕上げるもの・関連タスクの今の状態で 1 行ずつ。今日の予定は先頭に **今日**。
- プロジェクト → テーマごとのタスク(方針の「出す範囲」のとおり全件。期限が今日なら **今日**、7 日以内なら **7日以内** を期限の列の先頭に付ける)。
- 「状態の更新案」: 方針の「状態の確かめ方と更新案」のとおり、前日から今日までのセッション(orca worktree ps --since 1d)とコミット(worklog material、各リポジトリの git log)を台帳と突き合わせ、更新案を番号付きの表で出す(無ければ「更新案なし」と 1 行)。台帳は直さない。更新案があれば、Orca の item「状態の更新案(MM/DD)」を `orca bot item add` で作り、表を `--comment-file` に入れて `orca bot item set <n> --status needs-you --ask "この更新案で台帳を直してよいですか？" --option "全部直す" --option "一部だけ直す" --option "直さない" --recommended 1` で聞く。前日の同じ item が答えの無いまま残っていれば(`orca bot item list` で確かめる)、その案を含めてから `orca bot item cancel <n> --reason "翌日の item に引き継いだ"` で閉じる。チャットの結果には「状態の更新案は item『状態の更新案(MM/DD)』で確かめてください」と 1 行添える。
- 「今日の段取りの案」: 今日手を付けるとよいものを 3 つまで、ずらせない予定・期限の近さ・進行中かどうかを理由に 1 行ずつ。
```

## 日曜のタスク週次整理

- いつ: `FREQ=WEEKLY;BYDAY=SU;BYHOUR=9;BYMINUTE=0`(日曜 9:00)

```text
日曜のタスクの週次整理。来週(翌日の月曜〜その次の日曜)に向けて、タスクを取り組みごとに見渡し、来週の段取りを決める。

ハブのリポジトリ(~/Developer/<your-hub-repo>)の task-ledger skill(.agents/skills/task-ledger/SKILL.md)の「1. 一覧」の手順 1-1〜1-2 で、projects.yaml の全プロジェクトの台帳と priorities.md を読み、自分の担当のタスクを集める(read: origin/main のプロジェクトは fetch してから origin/main を読む)。読むだけで、台帳・priorities.md・どのリポジトリのファイルも書き換えない。コミットもしない。

出し方は この bot のフォルダの report-policy.md(タスク整理の方針)に従う。必ず最初に読む。方針と下の指示が食い違うときは方針を優先する。
- プロジェクトごと(projects.yaml の順)に見出しを分け、その中を方針のテーマで分ける。
- 方針のテーマに当たらないタスクは「未分類」にまとめ、最後に振り分けを聞く 1 行を添える。
- タスクは方針のとおり、プロジェクトごとに 1 つの表で出す。タスクは要点が分かる長さに縮めてよい。共同担当は「(共同: <自分以外の担当>)」を添える。
- SKIP・fetch の失敗があれば冒頭に書く。
- 日本語で、前置きなしに結果だけを書く。

この回で書くもの:
- 冒頭の 1 行: 来週の期間と「来週 n件・進行中 n件」。
- 「ずらせない予定」: この bot のフォルダの fixed-events.md を読み、来週の予定を、日時・予定・仕上げるもの・関連タスクの今の状態で 1 行ずつ。fixed-events.md のうち日時が過ぎた 1 回きりの予定の行は消してよい(このファイルだけは書き換えてよい)。消した行は最後に 1 行で知らせる。
- プロジェクト → テーマごとのタスク(方針の「出す範囲」のとおり全件。期限が来週なら **来週**、再来週なら **再来週** を期限の列の先頭に付ける)。
- 「状態の更新案」: 方針の「状態の確かめ方と更新案」のとおり、この 1 週間のセッションとコミットを台帳と突き合わせ、更新案を番号付きの表で出す(無ければ「更新案なし」と 1 行)。台帳は直さない。最後に「番号で答えてもらえれば Home のチャットで直します」と添える。
- 「来週の段取りの案」: 来週いちばん重いものを 3 つまで、理由を 1 行ずつ。ずらせない予定に間に合う順で、曜日ごとの割り振りの案があれば添える。
- 「着手を考えたいもの」: 期限の無い未着手のうち、来週手を付ける候補を 3 つまで。
```

## Home チャットのリセット

- いつ: `FREQ=WEEKLY;BYDAY=SU;BYHOUR=8;BYMINUTE=50`(日曜 8:50。週次整理の直前)
- 1 週間分のやり取りで Home チャットが長くなると、週次整理の結果が埋もれる。週の頭に Home チャットを始め直し、週次整理を新しいチャットで受け取る。SOUL.md・メモリー・item はそのまま残る。

```text
毎週日曜の Home チャットのリセット。日曜 9:00 のタスクの週次整理を新しい Home チャットで受け取るために行う。

1. `"${ORCA_CLI_COMMAND:-orca}" bot new-chat --bot "タスク管理"` を 1 回だけ実行し、新しい Home チャットを始める。SOUL.md・メモリー・item はそのまま残る。
2. ほかには何もしない(台帳もファイルも書き換えない)。失敗したときだけ、エラーの 1 行を最終メッセージに書く。成功したら最終メッセージは NO_REPLY だけにする。
```

## ずらせない予定のリマインド

`fixed-events.md` に書いた予定のうち、資料を仕上げる必要があるものは、前日に別のリマインドを作る。毎週の定例は毎週の定期実行に、1 回きりの打ち合わせは 1 回だけ動く定期実行にする。

### 毎週の定例

- いつ: `FREQ=WEEKLY;BYDAY=MO;BYHOUR=18;BYMINUTE=0`(火曜 10:00 の定例の前日 18:00)

```text
リマインド: 明日(火曜)10:00 に <定例の名前> がある。毎週の定例で、ずらせない予定。それまでに定例の資料を作る。

0. 最初に この bot のフォルダの fixed-events.md を読む。明日の定例が休み・移動と書かれていれば、何もせず、最後のメッセージを NO_REPLY だけにする。

1. <key> の台帳(projects.yaml の read のとおり。origin/main なら git fetch してから origin/main:tasks/index.md)を読む。読むだけで、何も書き換えない。
   - 担当が自分で、期限が明日までのもの
   - 進行中のもの
   - 直近の定例の議事録(<議事録の置き場> にある <定例の名前> の最新のもの)から出たもの
2. 次の形で短く知らせる。
   - 1 行目: 「明日 10:00 は <定例の名前>」
   - 定例で報告・相談しそうなことの案を 3 つまで(上で読んだタスクから。理由を 1 行ずつ)
   - 期限が明日までのタスクがあれば、その一覧
```

### 1 回きりの打ち合わせ

- いつ: 予定の 2 日前と前日の 18:00 に 1 回ずつ。`--trigger` の代わりに `--once --by <日時>` で 1 回だけ動く定期実行を作る(例 `--once --by 2026-12-03T18:00:00+09:00` と `--once --by 2026-12-04T18:00:00+09:00` の 2 つ)。
- 毎年同じ日に動く cron(`0 18 3,4 12 *`)で作るときは、`--precheck 'test "$(date +%Y)" = 2026'` を付けて翌年に動かないようにし、終わったら消す。

```text
リマインド: <日付>(<曜日>)<時刻> に <打ち合わせの名前> がある。ずらせない予定。それまでに <仕上げるもの> を仕上げる。

1. <key> の台帳(projects.yaml の read のとおり)を読み、次の行の期限・状態を確かめる。読むだけで、何も書き換えない。
   - <ID>(<仕上げるもの> を作るタスク)
   - <ID> を親に持つ行
   - 担当が自分で進行中の、関係しそうなタスク
2. 次の形で短く知らせる。
   - 1 行目: 「<打ち合わせの名前> まであと n 日(<日付>(<曜日>)<時刻>)」
   - 上のタスクの状態を 1 行ずつ
   - 今日から打ち合わせまでにやることの案を 3 つまで
```
