# タスク管理

台帳がリポジトリごとに分かれていて、今日なにから手を付けるかを決めるたびに台帳を見比べている人向けの bot です。毎朝、各リポジトリの台帳から自分の担当のタスクを取り組みごとにまとめた 1 週間の段取りが Orca のチャットに届きます。直近の作業から状態が変わったと読めるタスクは更新案として届くので、番号で答えるだけで台帳を今の状態に保てます。

## 前提

- **各リポジトリのタスク台帳**: [project-context-template](https://github.com/Kyo1M/project-context-template) の `tasks/index.md` と同じ形の台帳(「進行中」「完了」の 2 節と、決まった列)が、対象のリポジトリそれぞれにあること。テンプレートから作ったリポジトリなら、そのまま使えます。
- **ハブのリポジトリ**: 台帳を横断して読むための小さなリポジトリを 1 つ作ります。[hub-example/](hub-example/) をそのまま写して `~/Developer/<your-hub-repo>` に置き、次を書き換えます。
  - `projects.yaml`: `owner` を台帳の「担当」の列に書く自分の名前に、`projects` を自分のリポジトリにする(書き方はファイルのコメント)。
  - `priorities.md`: 例の行を消す(優先度は bot との相談で足していきます)。
  - task-ledger skill(`.agents/skills/task-ledger/SKILL.md`): このリポジトリでだけ使う skill です。`.claude/skills/task-ledger` は symlink なので、写すときに symlink のまま写します。
- **直近の作業を読む道具**(状態の更新案に使う。無くても一覧は出ます)
  - `orca worktree ps --since 1d`: Orca のセッションの依頼と返答
  - [claude-worklog](https://github.com/Kyo1M/claude-worklog) の `worklog material`: Claude Code と Codex のセッションとコミット
- **bot のフォルダに置く 2 つのファイル**(自分用。リポジトリには入れません)
  - `report-policy.md`: タスク整理の方針。どのタスクまで出すか、プロジェクトの中をどのテーマで分けるか、状態をどう確かめるかを書き、オーナーのフィードバックで bot が書き足していきます。
  - `fixed-events.md`: ずらせない予定(定例・締め切り・打ち合わせ)の一覧。

`report-policy.md` は次の節から始めると、定期実行のプロンプトがそのまま使えます。

```markdown
# タスク整理の方針

## 目的
(何のためにタスクを見渡すか。例: 毎朝、今日やることを 3 つに絞る)

## 出す範囲
(出すタスクの条件。例: 担当が自分の進行中の全件。期限の無い未着手も出す)

## 状態の確かめ方と更新案
(台帳と照らす材料と、更新案にする条件。例: その日のセッションで完了と言っているものは「完了」の案にする)

## まとまり(テーマ)
### <key>
(このプロジェクトのタスクを分けるテーマと、それぞれに入るタスクの目安)

## 直した記録
(フィードバックで方針を直した日と中身を 1 行ずつ)
```

`fixed-events.md` は 1 行 1 予定で書きます。

```markdown
# ずらせない予定

| 日時 | 予定 | 仕上げるもの | 関連タスク |
|---|---|---|---|
| 毎週金曜 9:30 | チームの定例 | 定例の資料 | research:#12 |
| 2026-12-05 14:00 | 顧客との打ち合わせ | 提案の資料 | webshop:T-12 |
```

## Orca での作り方

1. **bot を作る**: Orca で新しい bot を作り、名前を「タスク管理」にします。bot のフォルダは `~/.orca/bots/` の下にでき、`orca bot list` で場所を確かめられます。
2. **SOUL.md を貼る**: [SOUL.md](SOUL.md) の `~/Developer/<your-hub-repo>` を自分のハブのリポジトリに直し、bot のフォルダの `SOUL.md` を置き換えます。bot のチャットに貼って「SOUL.md をこの内容にして」と頼んでもかまいません。
3. **方針と予定のファイルを置く**: 上の型で `report-policy.md` と `fixed-events.md` を bot のフォルダに作ります。
4. **定期実行を足す**: [automations.md](automations.md) の 4 種類を足します。まず毎朝のタスク確認を作り、`orca automations run` で 1 回動かして結果を確かめてから、残りを足すと調整が楽です。

## この bot がしないこと

- 一覧を作るときに台帳を書き換えること。直すのは、更新案にオーナーが答えたあとか、チャットで頼まれたときだけです。
- `write: handoff` のプロジェクトの台帳をハブから直すこと。そのリポジトリのセッションに貼る引き継ぎ文を出します。
