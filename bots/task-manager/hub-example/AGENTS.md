# タスクのハブ(例)

複数のリポジトリのタスク台帳を読み、自分の担当のタスクを優先度と期限の順に並べるためのリポジトリです。状態の正本は各リポジトリの台帳で、このリポジトリは登録簿と優先度だけを持ちます。横断の一覧はファイルに残さず、`task-ledger` skill が毎回台帳から組み立てて会話に出します。期限切れの棚卸しも `task-ledger` skill で行い、自分専用の台帳(`write: ledger`)はここから直し、チームの台帳(`write: handoff`)にはそのリポジトリのセッションに貼る引き継ぎ文を出します。

## ファイルの役割

| ファイル | 持つもの |
|---|---|
| `projects.yaml` | 登録簿。担当の名前(`owner`)と、プロジェクトごとのリポジトリ・台帳のパス・読み方(`read`)・棚卸しの書き先(`write`) |
| `priorities.md` | 優先度。参照(`<key>:<台帳の ID>`)・タスク(写し)・優先度・メモの表 |
| `.agents/skills/task-ledger/SKILL.md` | 一覧の出し方・優先度の相談・片付け・期限切れの棚卸しの手順(`.claude/skills/task-ledger` は symlink) |

## 運用ルール

- 各リポジトリの台帳をここから書き換えるのは、`write: ledger` のプロジェクトの棚卸しと、個別に指定された状態・期限の変更だけ。タスクの追加・タスク名の変更は各リポジトリで行う(見送りのときにタスク名の末尾に付ける「(見送り)」は除く)。
- 台帳を書くときは、そのリポジトリの運用ガイドの台帳の型と、AGENTS.md の Git の決まりに従う(このリポジトリの「コミットして push する」は当てはめない)。
- `write: handoff` のプロジェクトの台帳・Issue は書き換えない。
- `priorities.md` に状態・期限・担当を持たない。毎回台帳から読む。
- 優先度は高・中・低の 3 段階。行の無いタスクは「未設定」として扱う。
- `priorities.md` を書き換えたらコミットして push する。
- プロジェクトを足すときは `projects.yaml` に 1 項目を足す。`write` を書かなければ `handoff`(台帳に書かない)として扱う。台帳が [project-context-template](https://github.com/Kyo1M/project-context-template) の `tasks/index.md` と同じ形であることが前提。
  - 「進行中」の節: `| ID | タスク | 担当 | 期限 | 親 | 出典 | 詳細 | 状態 |`
  - 「完了」の節: `| ID | タスク | 担当 | 完了日 | 親 | 出典 | 詳細 |`
  - ID は台帳の文字列をそのまま参照に使う(`T-12` のほか、Issue 番号を ID にする台帳では `#12` もある)。
